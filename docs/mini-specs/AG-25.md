## 2. Invariants & Scope Boundaries

### Invariants bắt buộc:
1. **Invariant "Log không lộ secrets" (Master Plan AG-25)**:
   - Mọi log ghi nhận ra stdout/stderr (dưới dạng JSON hoặc text) đều phải được lọc qua bộ khử nhạy cảm (`redactSensitiveData`).
   - Các trường bị xóa/mask: `password`, `secret`, `token`, `authorization`, `cookie`, `database_url`, hoặc bất kỳ chuỗi connection string nào có định dạng `postgres://...:...@...`.
2. **Bảo mật phản hồi Healthcheck**:
   - Endpoint `/api/health` chỉ thông báo trạng thái hoạt động tổng quan (`healthy` / `unhealthy`), trạng thái DB (`connected` / `disconnected`), uptime, version.
   - Khi DB gặp sự cố kết nối, tuyệt đối **không rò rỉ stack trace nội bộ, tên bảng hay chuỗi kết nối chứa credentials** trong response body hay exception.
3. **Kiến trúc Containerization độc lập (D20)**:
   - Ứng dụng chạy trong container Next.js standalone với người dùng không đặc quyền (`USER nextjs:nodejs`), base alpine nhẹ.
   - Dữ liệu cơ sở dữ liệu (`pgdata`) và tệp ảnh tải lên (`uploads_data`) được lưu trữ bền vững qua Docker Volumes trên VPS (D34).

## 3. Kiến trúc & Thiết kế kỹ thuật

### 3.1. Structured Logger & Redaction Utility (`src/lib/logger.ts`)
- Cung cấp các phương thức chuẩn: `logger.info()`, `logger.warn()`, `logger.error()`, `logger.debug()`.
- Định dạng JSON trong production cho phép các hệ thống log aggregator (như Vector, Loki, CloudWatch) dễ dàng thu thập và phân tích.
- Thuật toán `redactSensitiveData(data)` duyệt đệ quy object/array/string:
  - Mask các khóa nhạy cảm khớp danh sách (`password`, `token`, `secret`, `jwt`, `authorization`, `cookie`, `connection_string`, v.v.) thành `"[REDACTED]"`.
  - Thay thế chuỗi kết nối PostgreSQL dạng `postgres://user:pass@host:port/db` thành `postgres://user:[REDACTED]@host:port/db`.

### 3.2. Healthcheck Endpoint (`src/app/api/health/route.ts`)
- Phương thức `GET /api/health`.
- Kiểm tra tính sống của cơ sở dữ liệu: `await db.execute(sql\`SELECT 1\`)`.
- Kết quả:
  - Nếu kết nối DB thành công: Trả về HTTP 200 OK:
    ```json
    {
      "status": "healthy",
      "timestamp": "2026-10-20T...",
      "uptimeSeconds": 1234,
      "environment": "production",
      "version": "0.1.0",
      "database": "connected"
    }
    ```
  - Nếu mất kết nối DB: Trả về HTTP 503 Service Unavailable:
    ```json
    {
      "status": "unhealthy",
      "timestamp": "2026-10-20T...",
      "uptimeSeconds": 1234,
      "environment": "production",
      "version": "0.1.0",
      "database": "disconnected",
      "error": "Database connection failed"
    }
    ```

### 3.3. Tối ưu Docker Compose & Healthcheck Orchestration (`docker-compose.yml`)
- Thêm healthcheck vào service `web`:
  - Dùng script node inline hoặc `wget` kiểm tra `http://localhost:3000/api/health`.
- Service `caddy` phụ thuộc `web`: `condition: service_healthy` để không định tuyến người dùng vào container khi web chưa sẵn sàng.
