## 1. MỤC TIÊU & BỐI CẢNH

Sau khi hoàn thiện trọn vẹn từ nền tảng P1 đến P6 (đạt 288/288 tests PASS), dự án Ăn Gì Mom tiến sang **Phase P7** nhằm giải quyết trọn vẹn 3 nhu cầu cấp thiết nhất của người nội trợ hiện đại:
1. **AG-39 (Mở rộng thể loại món ăn)**: Đưa các món nước ăn trọn bữa (`ONE_DISH_MEAL`: Phở, Bún bò, Miến măng, Bánh canh), món chay chuẩn nhãn thanh tịnh/thuần chay (`VEGETARIAN`, `VEGAN`), và đồ uống / tráng miệng (`BEVERAGE`, `DESSERT`: Chè bưởi, Nước sâm) vào catalog chuẩn vị Việt.
2. **AG-40 (Kho thực phẩm / Tủ lạnh gia đình - Pantry)**: Giúp người nội trợ quản lý nguyên liệu sẵn có trong tủ lạnh/kho khô, phân loại vị trí bảo quản (`FRIDGE`, `FREEZER`, `DRY_PANTRY`), theo dõi hạn sử dụng, tự động nhận diện nguyên liệu sẵn có khi xem công thức để tránh mua thừa và hỗ trợ đồng bộ 1-chạm từ Giỏ đi chợ vào Tủ lạnh (`Shopping -> Pantry`).
3. **AG-41 (Kế hoạch mâm cơm tuần - Weekly Meal Planner)**: Lịch 7 ngày (Thứ 2 đến Chủ nhật) cho 4 bữa (Sáng/Trưa/Tối/Phụ). Cho phép gán công thức từ catalog hoặc món tùy chỉnh, 1-chạm xuất toàn bộ nguyên liệu cần đi chợ cho cả tuần sang Giỏ hàng (`Planner -> Shopping List`), và 1-chạm ghi nhận bữa đã nấu vào Nhật ký dinh dưỡng (`Planner -> Meal Diary`).

## 2. INVARIANTS BẮT BUỘC (GATE P7)

1. **Taxonomy & Role Consistency**: Không phá vỡ hệ thống vai trò mâm cơm (`meal_role`). Món nước tự thân trọn bữa dùng `ONE_DISH_MEAL`. Món chay dùng nhãn chuẩn trong `DIET_PREFERENCE` (Ăn chay thuần Vegan / Ăn chay thanh tịnh). Đồ uống dùng `BEVERAGE`, tráng miệng dùng `DESSERT`.
2. **Pantry Ownership & State**: Bảng `pantry_items` gắn chặt với `userId`. Người dùng này không thể xem, sửa hoặc xóa thực phẩm trong tủ lạnh của người dùng khác. Đơn vị đo lường tuân thủ bộ chuyển đổi bếp Việt (`units.ts`).
3. **Smart Pantry Matching (Không ép mua trùng)**: Khi xem công thức, hệ thống đối chiếu danh sách nguyên liệu của công thức với nguyên liệu hiện có trong `pantry_items` (theo `ingredientId` hoặc chuẩn hóa tên tiếng Việt). Trả về danh sách: "Đã có sẵn trong nhà" và "Cần mua thêm".
4. **Weekly Planner Integrity**: Kế hoạch tuần lưu theo ngày `planDate` (`YYYY-MM-DD`), buổi ăn `mealType`, và số khẩu phần `servings`. Người dùng có thể đánh dấu hoàn thành `isCompleted = true` và đồng bộ tức thời vào `meal_diary_entries` mà không tạo sai lệch calo.
5. **Seamless Shopping Integration**:
   - `Shopping -> Pantry`: Chỉ chuyển những món đã được check `checked = true` trong giỏ hàng vào tủ lạnh.
   - `Planner -> Shopping`: Tổng hợp chính xác số lượng nguyên liệu của tất cả món trong tuần (nhân theo `servings`), loại trừ những món đã có sẵn trong Tủ lạnh nếu người dùng bật tùy chọn "Trừ nguyên liệu đã có sẵn".

## 3. DATA MODEL & SCHEMA

### 3.1. Enum Mới
- `storage_location`: `'FRIDGE'`, `'FREEZER'`, `'DRY_PANTRY'`

### 3.2. Bảng `pantry_items`
```sql
CREATE TABLE pantry_items (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  ingredient_id INTEGER REFERENCES ingredients(id) ON DELETE SET NULL,
  custom_name TEXT NOT NULL,
  quantity DOUBLE PRECISION NOT NULL DEFAULT 1.0,
  unit TEXT NOT NULL DEFAULT 'gam',
  location storage_location NOT NULL DEFAULT 'FRIDGE',
  expires_at TIMESTAMP WITH TIME ZONE,
  notes TEXT,
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);
CREATE INDEX pantry_items_user_idx ON pantry_items(user_id);
CREATE INDEX pantry_items_expires_idx ON pantry_items(expires_at);
```

### 3.3. Bảng `meal_plans`
```sql
CREATE TABLE meal_plans (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  plan_date TEXT NOT NULL, -- YYYY-MM-DD
  day_of_week INTEGER NOT NULL, -- 1 = T2 ... 7 = CN
  meal_type diary_meal_type NOT NULL DEFAULT 'LUNCH',
  recipe_id INTEGER REFERENCES recipes(id) ON DELETE SET NULL,
  custom_dish_name TEXT,
  servings INTEGER NOT NULL DEFAULT 4,
  notes TEXT,
  is_completed BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);
CREATE INDEX meal_plans_user_date_idx ON meal_plans(user_id, plan_date);
CREATE INDEX meal_plans_recipe_idx ON meal_plans(recipe_id);
```

## 4. API ENDPOINTS

1. **Catalog Mở rộng (AG-39)**:
   - `GET /api/recipes?role=ONE_DISH_MEAL`: Lọc các món nước ăn trọn bữa (Phở, Bún bò...).
   - `GET /api/recipes?tag=an-chay-thuan`: Lọc món chay thuần.
   - `GET /api/recipes?role=BEVERAGE,DESSERT`: Lọc đồ uống & món tráng miệng.

2. **Tủ Lạnh & Kho Bếp (AG-40)**:
   - `GET /api/pantry`: Lấy danh sách thực phẩm trong kho của user, lọc theo vị trí và trạng thái hạn sử dụng (sắp hết hạn trong 3 ngày).
   - `POST /api/pantry`: Thêm thực phẩm mới vào kho.
   - `PUT /api/pantry/[id]`: Cập nhật số lượng, vị trí, hạn dùng.
   - `DELETE /api/pantry/[id]`: Xóa thực phẩm.
   - `POST /api/pantry/sync-from-shopping`: Chuyển các món đã mua trong giỏ vào tủ lạnh.
   - `GET /api/recipes/[id]/pantry-check`: Đối chiếu nguyên liệu công thức với tủ lạnh xem đã có gì và thiếu gì.

3. **Kế Hoạch Bữa Cơm Tuần (AG-41)**:
   - `GET /api/meal-plans?weekStart=YYYY-MM-DD`: Lấy kế hoạch 7 ngày trong tuần.
   - `POST /api/meal-plans`: Thêm món vào kế hoạch một ngày cụ thể.
   - `PUT /api/meal-plans/[id]`: Đổi món, đổi số khẩu phần hoặc đánh dấu hoàn thành.
   - `DELETE /api/meal-plans/[id]`: Xóa món khỏi kế hoạch.
   - `POST /api/meal-plans/to-shopping`: Tổng hợp nguyên liệu của kế hoạch tuần đưa vào Giỏ đi chợ (hỗ trợ cờ `excludePantry: boolean`).
   - `POST /api/meal-plans/[id]/log-to-diary`: Nấu xong, tự động ghi món vào Nhật ký dinh dưỡng gia đình.
