## 1. Context
- Bắt buộc đọc: [AN_GI_MOM_MASTER_PLAN.md](../AN_GI_MOM_MASTER_PLAN.md) (§5.2, §7.3), [ARCH.md](../ARCH.md) (§3.3), [DECISIONS.md](../DECISIONS.md) (D17, D20, D31, D33).
- Trạng thái hiện tại: Đã hoàn tất Trình biên tập công thức có cấu trúc (AG-13). Để công thức món cơm nhà hiển thị sống động, kích thích vị giác và minh họa rõ ràng các bước thực hiện, dự án cần bước thứ sáu của Phase P2: **Xây dựng Pipeline xử lý và lưu trữ đa phương tiện (Media Pipeline) cho hình ảnh món ăn và các bước nấu**.
- Invariants & Chiến lược kỹ thuật cốt lõi:
  - **Tự chủ hạ tầng & Không vendor lock-in (D17, D20)**:
    - Mặc định lưu trữ ảnh trên Local Storage (thư mục `public/uploads/` được mount Docker Volume liên tục trên VPS riêng của chủ sản phẩm), không phát sinh chi phí SaaS hàng tháng.
    - Cấu trúc mã theo mẫu Storage Adapter để có thể cắm S3/Cloudflare R2 trong tương lai mà không cần viết lại ứng dụng.
  - **Bảo mật tệp tải lên (Security Boundaries)**:
    - Chỉ cho phép người dùng có quyền `EDITOR` hoặc `ADMIN` tải ảnh lên.
    - Kiểm tra nghiêm ngặt Content-Type / MIME type: chỉ chấp nhận `image/jpeg`, `image/png`, `image/webp`, `image/avif`.
    - Giới hạn dung lượng tối đa 5MB / ảnh.
    - Đặt tên tệp ngẫu nhiên an toàn bằng `crypto.randomUUID()` kết hợp timestamp để ngăn chặn Directory Traversal và ghi đè tệp.
  - **Trải nghiệm biên tập mượt mà**:
    - Tích hợp trực tiếp trình chọn và xem trước (Preview) ảnh đại diện món ăn và ảnh minh họa từng bước nấu ngay trong giao diện `/editor/recipes/new` và `/editor/recipes/[id]`.

## 2. Invariants & Scope Boundaries
- **Phạm vi của AG-14**:
  1. **Upload API Endpoint**:
     - `POST /api/upload`: Nhận `multipart/form-data`, xác thực session `EDITOR`/`ADMIN`, lưu tệp vào `public/uploads/recipes/`, trả về `{ url: '/uploads/recipes/<filename>' }`.
     - `GET /uploads/*`: Phục vụ tệp tĩnh qua Next.js / Caddy.
  2. **Storage Management**:
     - Tạo thư mục `public/uploads/recipes` và thêm vào `.gitignore` (chỉ commit file `.gitkeep` để giữ cấu trúc thư mục).
     - Cập nhật `docker-compose.yml` để tạo volume lưu trữ bền vững `angimom_uploads` mount vào `/app/public/uploads`.
  3. **Tích hợp giao diện Editor**:
     - Cập nhật `/editor/recipes/new` và `/editor/recipes/[id]`:
       - Thay thế ô nhập link ảnh đơn thuần bằng Upload Component có nút "Tải ảnh lên", xem trước tức thì, hiển thị kích thước tệp và nút gỡ bỏ ảnh.
       - Hỗ trợ tải ảnh minh họa cho từng bước nấu (Cooking Steps).
- **Ngoài phạm vi AG-14**:
  - Video streaming hoặc nén video (dành cho các giai đoạn sau).
  - Phê duyệt xuất bản bài viết công khai (thuộc AG-15).

## 3. Implementation Plan
1. **Upload Service & API**:
   - `src/lib/storage/index.ts`: Module xử lý lưu trữ tệp tin (ghi file đệm an toàn, kiểm tra MIME type, kích thước).
   - `src/app/api/upload/route.ts`: Endpoint tiếp nhận tệp tải lên, bảo vệ bởi `getSessionUser()`.
2. **Container Volume Persistence**:
   - Cập nhật `docker-compose.yml`: bổ sung volume `uploads_data:/app/public/uploads` cho service `web`.
3. **Editor Component Integration**:
   - Tạo component `src/components/ui/ImageUpload.tsx` tái sử dụng cho cả Hero Image và Cooking Step Images.
   - Tích hợp vào `/editor/recipes/new/page.tsx` và `/editor/recipes/[id]/page.tsx`.
4. **Kiểm thử & Xác minh**:
   - Viết script kiểm thử tải ảnh lên qua API, kiểm tra lọc file độc hại / dung lượng vượt ngưỡng.
   - Kiểm tra `npm run build` thành công 100%.

## 4. Acceptance Criteria
- [ ] API `POST /api/upload` tiếp nhận ảnh hợp lệ, từ chối tệp không phải ảnh hoặc vượt quá 5MB.
- [ ] Ảnh tải lên được lưu thành công vào `public/uploads/recipes/` và truy cập được qua HTTP URL.
- [ ] `docker-compose.yml` được cấu hình volume lưu trữ bền vững cho uploads.
- [ ] Giao diện soạn thảo và chỉnh sửa công thức có component tải ảnh trực quan, hiển thị preview mượt mà.
- [ ] `npm run build` pass 100% không cảnh báo lỗi.
